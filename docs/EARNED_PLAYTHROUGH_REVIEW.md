# Earned Playthrough Review

## Verified Route

The September 13 local build completed the earned checkpoint chain from the
opening through source-note repair, annotation-cart exploration, network
routing, clearance, referral dispatch, editorial repair, proofing, production,
DANN-E and publication. Checkpoints came from browser storage exports after
physical traversal and interactions, not tool grants or direct scene starts.
This was a chained automated keyboard playthrough, not one uninterrupted human
session or an unaided novice usability test.

Final verification used `qa-earned-production.mjs`, `qa-boss-counter-loop.mjs
--boast-skip`, and `qa-bindery-finale.mjs`. These accept `FRUS_QA_STORAGE` and
`FRUS_QA_OUT`; browser paths can be configured with `PLAYWRIGHT_MODULE` and
`CHROMIUM_EXECUTABLE`.

- Production: wrong typeset proof rejected; two actual textual changes repaired;
  filing did not prematurely award the key; stamping earned Buckram Key.
- Boss: colossus, swarm and cloud cleared; seven return-and-counter cycles,
  seven fresh core hits, no retries, deadline not missed. The harness uses
  projectile position/timing readouts, so this does not establish human difficulty.
- Bindery: failed index attempt kept progress and reliability; pending human
  certification survived reload; separate press action published the volume.
- Publication: 241 document points, reliability 100, five cover pieces,
  three defeated variants, clean publication, deadline met. Completion stats
  and inventory remained unchanged after reload. No captured page/console errors
  in the final boss or bindery runs.

Local artifacts are under `/private/tmp/frus-earned-production/`,
`/private/tmp/frus-earned-final-boss/`, and `/private/tmp/frus-earned-publication/`.
They are temporary evidence, not public release assets. The new earned
publication checkpoint is `earned-publication-storage.json` in the last folder.

## What Works

- A physical source clue changes a draft and opens a route: this is the strongest
  fit between archival research and adventure-game discovery.
- Cart routing and the Dispatch Stacks return shortcut reward spatial play.
- Tool rewards have demonstrated consequences across rooms, not just inventory labels.
- DANN-E provides a distinct action climax with a readable return/open-core rhythm.
- Proof corrections test meaningful differences: record identity, release scope,
  event versus drafting date, and preservation of wording.

## Next Design Work

1. Shorten the post-boss bindery. Five more station deliveries dissipate the
   climax, and index repair duplicates the preceding production task. Preserve
   accountable final certification and an explicit publication action, but make
   the rest a visible assembly payoff for work already earned.
2. Audit delivery-only stretches. Retain errands when they teach geography or
   set up a discovery; replace repeated walk-confirm-stamp beats with fewer,
   consequential interactions.
3. Test DANN-E using visible cues and imperfect human timing, including touch.
   The passing scripted counter route is not a substitute for this.
4. Observe a fresh player without directions. Measure where they hesitate,
   whether the next destination is apparent, and whether new tools feel useful.

Do not equate passing the route with the full fun objective. Optional exploration,
novice comprehension, pacing, and physical-device play remain separate checks.
